# Standards for every tool page

Set by the site owner on 26 Nov 2026 after reviewing the pricing calculator. They apply to every future tool.

1. The promise matches the math. Headline, labels and result describe the same quantity (session price vs hourly rate). If both are useful, show both.
2. Never show an invalid result. Validate every input and the final result (finite, inside a stated range). Show a clear message naming the field and the allowed range. Test huge, empty, zero, negative and fractional values.
3. Say what the result means. State what is calculated, whether it is before tax, and that it is not a market price or a promise of customers.
4. Every calculator has a visible worked example whose numbers can be checked by hand, using the default inputs.
5. Assumptions are visible. If a package is just price x 10, say so. If a discount is added, show how it changes the result and what it assumes.
6. The tool comes first. Short header, small decoration, inputs and result visible quickly, especially on mobile. Decoration never pushes the tool down.
7. Affiliate disclosure speaks to the visitor: short, clear, placed right before the link. No internal notes about payout status.
8. An offer must relate to the visitor's need before its button. Say why it is next to the tool and who it suits. Keep tested / not tested separate. Give a test date only if it is recorded; otherwise say it is not recorded.
9. Each page has its own title and meta description that describe that page. The description must not repeat the title.
10. Links: canonical points to the page itself; English and Arabic pages point to each other with hreflang; main pages are in the sitemap.
11. Supporting text serves use of the tool: short how-to, meaning of inputs, limits, real questions. No word-count targets, no keyword repetition.
12. A tool is accepted only after real checks: known result, empty, zero, negative, fraction, huge numbers; then mobile, keyboard use and how result changes are announced to assistive tech. Do not claim a screen reader or device test that was not done.
13. Privacy text matches the code. Say what actually happens (for example: numbers are processed in your browser and not sent to a server; the page does not store them).
14. Structured data describes what the page really is. No invented ratings or reviews. Structured data does not guarantee rich results.
